# Walls (sub-project 07) — implementation plan

> **For agentic workers:** executed task by task, subagent-driven: a fresh
> implementer per task and an independent reviewer per task, then a final
> whole-branch review. Steps use checkbox (`- [ ]`) syntax.

**Goal:** walls in the floor planner. A wall is a straight centreline with a
thickness and a justification, drawn as a solid band that cleans up where it
meets other walls — an asymmetric mitre at an L, a butt at a T, a cross at
an X, a clean star at three or more ends — regenerated inside the edit that
changes it. A chained Wall tool (W), end grips whose joined ends follow, and
a Wall section in the right panel.

**Architecture:**
- **The engine** (06's mechanism) gains generated **regions** (a fill and its
  boundary), an **on-demand neighbour search** (O(k·n) per edit), and
  `ParametricType.diagnose`.
- **The render layer** gains one seam: an optional `ObjectGripProvider` on
  `GripCache`, used by `GripDrag` and the select tool.
- **The app** gains `WallParams`/`WallType`, pure wall geometry, the Wall
  tool, `WallGrips`, a Wall panel section with a pinned commit target, and
  one catalog for boxes and walls.

**Tech stack:** Dart, Flutter 3.47.2; `package:test`, `flutter_test`,
`vector_math`. No new dependency.

## Rulings made here rather than left to an implementer

Each says what the plan does, why, and what it costs if wrong. **(spec
amended)** rulings are written into the spec in Task 11.

- **Ruling 07-1 — undo mid-chain is swallowed (spec amended, D11).** Spec
  D11 says "undo mid-chain removes the last wall". `PlacementTool.onKey`
  swallows every key-down while a shape is pending (05 D3,
  `placement_tool.dart:186-190`) so undo never lands on a half-placed
  shape; the Wall tool keeps that rule. Esc or Enter ends the chain; then
  cmd+Z undoes the last wall. A click on the chain's **last** point ends it
  too (the Polyline tool's self-snap, `polyline_tool.dart:23-31`), so a
  double click is harmless. **Cost if wrong:** one extra Esc.
- **Ruling 07-2 — wall geometry is app code, pure Dart.**
  `apps/floor_planner/lib/parametric/wall_geometry.dart` imports no Flutter
  and is tested with `flutter test` like the rest of the app. **Cost:** none.
- **Ruling 07-3 — node membership (spec D4).** For an end at `p`: the
  candidates are every neighbour end within `wallJoin.linear` of `p`, plus
  this end; the **anchor** is the lowest `(handle, end index)` among them;
  the members are every end (this wall's and the neighbours') within
  `wallJoin.linear` of the anchor's endpoint. Every member computes the same
  set unless ends spread beyond `2 × wallJoin.linear`, which snapping never
  produces. **Cost if wrong:** a pathological cluster computes inconsistent
  caps; `drift()` stays empty (generation is still a function of parameters).
- **Ruling 07-4 — two ends in one direction** (spec D5.1, `sweep` of 0 or
  2π): both keep free caps and the node is built from the remaining ends.
- **Ruling 07-5 — where D10 is measured.** A test,
  `packages/jet_cad_2d/test/parametric/neighbour_cost_test.dart`, builds 100,
  300 and 600 segment-shaped test objects, times a plain line draw and an
  object move with `Stopwatch` (printed, not asserted), and asserts the
  overlap-test counter. The printed numbers go into the results note.
- **Ruling 07-6 — the container cannot build macOS.** This plan runs in a
  Linux container: engine, render, harness and app suites, analyze, format
  and `flutter build web --release` run here; **`flutter build macos
  --release` and the look are the human's**, recorded as owed.
- **Ruling 07-7 — Linux-only failures.** On Linux x86_64 `main` fails two
  byte-hash tests in `test/testing/generate_document_test.dart` (spike
  finding 7). The same holds for the render layer's
  `text_lod_ladder_golden_test.dart` rungs 1-2, Linux-only golden failures
  measured at the branch point. They are standing failures **here only**;
  no task fixes or counts them. Any other failure is real.
- **Ruling 07-8 — the region test client duplicates nothing of the wall.**
  Engine tests cannot import the app; `test/parametric/support/clients.dart`
  gains `RegionRect` (a rotated rectangle generating `count` regions and one
  LINE), so the planner is tested without wall geometry (06 Ruling 06-9's
  reasoning).

## Global Constraints

- **Pure-Dart engine.** Nothing under `packages/jet_cad_2d` imports Flutter
  or `dart:ui`; neither does `wall_geometry.dart`.
- **`unused_import` and `unused_element` are errors** in the render layer
  and the app.
- **The frame path allocates nothing new.** `query_allocation_test.dart` and
  `paint_allocation_test.dart` stay green **and unedited**.
- **Draw order is ascending handle value.** A wall's three children keep
  their handles for its whole life.
- **Decisions use `wallJoin` (or `Tolerance`); stored values use `==`.**
- **World is root space.** Never read or write the root's transform.
- **Never commit `analysis_options.yaml`.** `git status --short` before every
  commit; `flutter pub get` rewrites `packages/jet_cad/analysis_options.yaml`.
- **Never `git checkout --` a `.dart` file.** `cp` a backup, mutate, restore
  from the copy, `diff` to prove it.
- **Never synthesize test output.** Paste what ran: the summary line and the
  exit code.
- **Prefix every test command with `CI=true`**; Flutter is at
  `/root/flutter/bin` (`export PATH=/root/flutter/bin:$PATH`).
- **English** in code, comments and commits. **Every commit ends with:**
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **`dart format`** every file you touch before the gate.
- **Fixtures are off the identity:**
  - wall plans sit at the **far origin** `(4500000, 1200000)`;
  - every relational fixture is **rotated**, and each wall of a joint sits in
    its **own** group transform (translation · rotation, never 0° or 90°);
  - the degenerate 90° equal-thickness centre fixture may appear only as a
    control, never as the sole fixture of a test;
  - relational tests assert **coordinates** (shared corners, oracle corners)
    and counts.
- **Every task ends green.** Gate lines (Linux container):

  ```sh

  cd packages/jet_cad_2d         && CI=true dart test ; dart analyze && dart format --output=none --set-exit-if-changed .
  ```

  - **Standing failures:** the engine's two Linux-only hash tests and the
    render layer's two Linux-only `text_lod_ladder` rungs (Ruling 07-7); the

## Review Focus

Inputs a person will hit that no exit criterion names. Each has a test.

1. **Drawing a closed rectangular room with W** (four clicks, click the
   start): four walls, four mitres, `drift()` empty, four undo steps.
   Task 6, `WT4`.
2. **Selecting one wall of an L and pressing Delete:** the survivor's end
   squares; cmd+Z restores the mitre. Task 5, `WR7`.
3. **Dragging the shared corner of an L with the end grip:** both walls
   follow, one undo step. Task 7, `EG3`.
4. **Changing a wall's justification in the panel** while it is joined:
   both walls' corners move. Task 8, `WS4`.
5. **Drawing a wall through the middle of another (an X), then a T onto
   it:** X stays two rectangles; the T butts the near face. Task 5, `WR5`.

### Task 1: Regions in the planner (spec D8)

**Files:** `parametric_system.dart`, `regeneration.dart`,
`test/parametric/support/clients.dart`, `test/parametric/regions_test.dart`.

- [ ] **Step 1 — `Generated`.** Add `final bool filled`; the existing
  constructor sets `false` and still refuses `EntityKind.fill`; add
  `Generated.region(GeometryPayload boundary)`: `kind = polyline`,
  `filled = true`. Doc comment: a closed POLYLINE and the FILL naming it;
  the planner rewrites only the boundary.
- [ ] **Step 2 — `_plan`.** Port the spike's change
  (`git show spike/07-walls -- packages/jet_cad_2d/lib/src/parametric/regeneration.dart`):
  - collect this object's fill children; their boundaries (payload
    `scalars[0]`) are excluded from the plain-kind matching;
  - the *i*-th generated region ↔ the *i*-th fill child ascending: changed
    boundary → `SetEntityGeometryCommand(boundary, payload)`; missing →
    `AddRegionCommand(fill: draftRecord(++reserved, h, fill), boundary:
    draftRecord(++reserved, h, polyline), boundaryPayload: payload)`;
  - regions are planned **before** plain children, in generation order, so
    a new object's handles are fill < boundary < later children;
  - a surplus fill is removed **through its boundary**
    (`RemoveEntityCommand(boundary)`), sorted with the other surplus;
  - a boundary payload that is not a closed, triangulable polyline is a
    client bug: `_plan` throws `ArgumentError` (so `_run` rolls back).
- [ ] **Step 3 — the client.** `RegionRect(w, h, count)` and `RegionRectType`:
  `generate` emits `count` regions (nested rectangles inset by 10·i) plus one
  LINE (the diagonal); `reach` is the transformed rectangle's AABB.
- [ ] **Step 4 — tests** (every object at `atA`-style rotated placements):
  - `RG1` a new object gets `fill, polyline(boundary), line` with handles
    fill < boundary < line, and the fill's scalar names the boundary;
  - `RG2` a width edit rewrites the boundary **in place**: every child handle
    unchanged, the fill's triangulation updated (`doc.fills.trianglesFor`),
    one undo step, undo/redo exact (`canon`);
  - `RG3` `count` 1 → 2 adds one region (two handles above the seed, fill
    first); 2 → 1 removes the surplus **pair**: no orphan boundary, no
    dangling fill (M-07m);
  - `RG4` load → save byte-identical; `drift()` empty after reload;
  - `RG5` `SetEntityGeometryCommand` on a region boundary and on the fill
    both throw `GeneratedGeometryError`; bytes and undo depth unchanged;
  - `RG6` deleting the object with the select tool's order (boundaries, not
    fills, then the node) detaches the component; undo restores 3 children;
  - `RG7` a client emitting an open polyline as a region: the edit throws,
    nothing recorded, bytes unchanged;
  - `RG8` `Generated(EntityKind.fill, …)` still throws `ArgumentError`.
- [ ] **Step 5 — gate** (engine + render), commit
  `feat(engine): generated regions in the parametric planner (07 D8)`.
