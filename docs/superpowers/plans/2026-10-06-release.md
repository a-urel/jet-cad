### Task 2 — the standing comparison (P5, M-14d-q)

A Dart package at `tool/ci/` (`jet_cad_ci`, a workspace member, dev
dependency `test` only — already in the lock):

- `lib/standing.dart`: `Outcome compareRun(String json, {required
  String root, required Set<String> failures, required Set<String>
  skips})` — reads the JSON events; a test's id is `<suite path relative
  to root> :: <name>`; hidden tests (the loaders) count only when they
  fail; returns the unexpected failures, the standing failures that
  passed, the unexpected skips, the standing skips that ran, the
  VM-service skips, and whether the run ended (`done`).
- `expect_failures.dart` (the spec's script): `dart run
  tool/ci/expect_failures.dart --package <name> --root <dir> <json>`,
  reading the package's lines of `standing_failures.txt` and
  `standing_skips.txt` (`<package> | <suite> | <name>`), printing every
  difference, exit 1 on any.
- **Always red:** a run with no `done` event; a run with no test at all;
  a skip whose reason is the VM service's absence, even if listed.
- `test/standing_test.dart` on recorded fixtures (`test/fixtures/`, cut
  from real runs, both reporters): exactly the standing set → pass; a new
  failure → red; a standing failure passing → red; an extra skip → red; a
  VM-service skip → red, listed or not; a truncated run → red; `flutter
  test`'s absolute paths and `error` results read as `dart test`'s.
  **Mutants:** a subset comparison (standing failures that pass
  ignored); skips ignored; the VM-service rule removed; `done` not
  required.
