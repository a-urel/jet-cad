## 1. ByLayer drafting on layer 0 rendered white

**Cause.** Everything the app drafts is ByLayer on layer 0 (spec 05 D2), and
layer 0 is ACI 7. The resolver mapped ACI 7 through `aciToRgb(7)` =
0xFFFFFF, and nothing contrasted it with the paper.

**The rule (the human's decisions).** ACI 7 is AutoCAD's *foreground*
colour:

- `DocumentStyleResolver(document, {foreground = 0xFFFFFF})` resolves every
  ACI 7 to `foreground`, by any route: the entity's own colour, ByLayer,
  ByBlock, or the document root. The test is one integer compare on the
  encoded colour, so a `TrueColor(0xFFFFFF)` stays white. The default keeps
  every existing test and golden where it was.
- `foregroundFor(background)` (engine) picks black or white, whichever has
  the higher WCAG contrast against the paper. Luminance is sRGB-linearised
  and the paper's alpha is ignored. The crossover grey is 0x767676 → black,
  0x757575 → white; no 8-bit colour ties (checked exhaustively).
- The floor planner's shell derives the foreground from the page's
  background. It builds a new resolver only when the answer flips (White →
  Ivory keeps the instance; White → Blueprint swaps it), on every route the
  `PageNotifier` reports: the swatch, undo, redo, load and purge. A document
  without a page counts as white paper.
- **Walls keep their concrete black** (`kWallColor`, spec 07 D3).

Commits `c960d1e` (the foreground) and `754aa83` (it follows the paper). The
second came from F1's review, which found the navy Blueprint paper: a
hard-wired black would have taken drafting there from about 11.6:1
contrast to about 1.8:1.

## 2. The Page panel's Scale field kept focus after Enter

`PanelFieldFocusNode.handBack` (`apps/floor_planner/lib/panel_focus.dart`)
hands focus back through the scope's history, past every panel field in
either panel, to the node before them (the canvas). It starts from the node
that has the focus. The Scale field uses it on Enter and on a tap outside,
which also failed with a mouse.

The scale is still **committed on submit only** (spec 04). A tap elsewhere
in the app without Enter hands the focus back and shows the page's scale
again, read from the document. A window blur is never a tap, so switching
windows mid-edit keeps the typed text.

It took three review rounds to get there:

- `159ee7d` re-synced on any focus loss. Its comments misdescribed the
  order on Enter.
- `f5920de` read the document and added a lifecycle guard.
- The next review reproduced in Chromium, on the release build, that on
  web the `<input>`'s own blur closes the text connection while the app is
  still resumed. The typed text was still dropped on an alt-tab.
- `e0336f8` re-syncs in `onTapOutside` only. The final review repeated the
  Chromium run: 1:75 is kept after the blur and after resume, and an in-app
  tap shows 1:50.

Commits `e5c2a89`, `159ee7d`, `f5920de`, `e0336f8`.

## 3. Box m3: tapping the panel background refocused Width

The Selection panel's fields use the same `handBack` on Enter and on a tap

## Debt and known consequences

- **The canvas misses a resolver swap on its own** (F1b review, m1, which
  predates this branch). `_DraftCustomPainter.shouldRepaint` ignores the
  painter's identity, so on the vertices backend a host that swaps the
  resolver without a document edit paints stale colours until the next
  edit. The floor planner never does that: every paper change is an edit.
  The fix belongs in `jet_cad_2d_flutter`, with its own test.
- **Scale text left visible** (accepted by ruling). Leaving the Scale
  field by clicking another text field (all share one tap group) or by Tab
  keeps the unsubmitted text visible until the page changes.
- **Letters dead after a web alt-tab** (final review, which predates this
  branch). `EditableText.connectionClosed` unfocuses with the default
  disposition, so after an alt-tab mid-edit the focus ends on the route's
  scope. L does nothing until a canvas click. This happens on the old build
  and the new one alike.
- **The Text tool's pending entry is lost on a web alt-tab** (final review,
  which predates this branch). `text_entry_overlay.dart` uses the same
  lifecycle guard that `f5920de` did. In Chromium the web-order blur
  discards a pending entry, which breaks Ruling T7-b on web. A13 drives
  only lifecycle changes, so it cannot see this.
- **On Blueprint paper** (following the paper, the human's decision):
  - drafting that lies *off* the sheet is white on the light surround;
  - the grid is black-alpha, so it is nearly invisible;
  - the startup plan's concrete colours (walls 0x202020) stay dark;
  - walls are black.
- **Something to look at:**
  - draft a line, a rectangle and a box on White, then switch to Blueprint
    and back;
  - type a scale and press Enter, then press L;
  - type a scale and click the Page title;
  - type a scale, switch windows and come back;
  - in the Box fields, go Width → Height, tap the Box title, then press W.
