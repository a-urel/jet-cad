## The R5 decision: render the renderer's own `SymbolGallery`

The task offered two ways to fix R5. **I rendered the renderer's own public
`SymbolGallery`** (barrel only), and moved the plan-library picture to the
plan library's README as a new scene (`plan_gallery.png`). Why:

- **A11 puts a picture where the package is.** `PlanSymbolGallery` is the plan
  library's widget, so its gallery belongs in `jet_cad_2d_plan`'s README, which
  now carries `plan_gallery.png` (scene PL2).
- **The renderer ships a gallery of its own.** `SymbolGallery` and
  `SymbolThumbnails` are the renderer's public API, and the plan library's
  gallery is built on them. Dropping the picture would hide a widget the
  renderer publishes, so the renderer's README keeps a genuine gallery picture
  — now its own widget over a library the scene builds from plain engine
  shapes. Nothing under `src/` is imported; `symbolThumbnailDocument` (src-only)
  is not touched.

The alternative — drop `symbol_gallery.png` from the renderer's README and use
it in the plan library's — was rejected: the plan library now has a picture of
its own gallery widget, and the renderer's README would lose a picture of a
widget it gives.

The rewrite builds the gallery by hand: `GalleryCategory`/`GallerySymbol`
values (each with a `thumbnailDocument` over a small `DraftDocument`) and a
`SymbolThumbnails` cache, the thumbnails being lines, closed polylines,
circles and one arc via `addDrafted` (`foregroundFor` picks the ink). Three
categories (Furniture, Openings, Fixtures), one open.
