## What this branch does

The three published packages (0.7.1 on pub.dev) get what a pub.dev page
shows: a README with images, `screenshots:` in the pubspec, `funding:`
links, and a package table; all three go to **0.7.2**. The images are
generated by a new unpublished package, `tool/screenshots` (flutter_test,
real fonts, no pixel comparison). The README code is analysed in a second
tool package, `tool/readme_probe`. Two CI scripts keep both honest:
`check_readmes.dart` and `check_screenshots.dart`. R-10's two exports
(`SymbolLibraryState` family, `TableNumberProblem`) go on the planner's
barrel, which the 0.7.1 note had left as a 0.x candidate.

## Two facts for the record

1. **The renderer gained a code change.** The spec's original line was "no
   code change"; R6's Task 3b (`5600f4f`) changed
   `packages/jet_cad_2d_flutter/lib/src/ruler_frame.dart` and
   `ruler_painter.dart` (`RulerFrame.build` also went from an expression to
   a block body, about 145 lines of diff noise). The 0.7.2 CHANGELOG says
   so.
2. **The plan's Global Constraints were wrong about `SymbolWords`.** They
   list `SymbolWords` among the names the scenes may take from
   `package:jet_cad_floor_plan/editor.dart`; it is not exported there (nor
   by the planner barrel; only `SymbolNames` is). The renderer scene does
   not need it: `searchSymbols(entries, query, [SymbolWords words =
   SymbolWords.english])` takes it as an optional parameter, and the
   default gives `e.name` and `g.category`. The scene calls
   `searchSymbols(library.entries, '')`. Nothing is imported from `src/`.
