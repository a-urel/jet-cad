## Findings

1. **Minor (defect, file-only state) — a layer whose *stored* name fails D4 cannot be hidden, shown, locked or recoloured.**
   `SetLayerCommand`'s user form (`packages/jet_cad_2d/lib/src/document/layer_commands.dart:288-291`) runs `layerNameError(target, record.name, self: handle)` even when the name is unchanged. A name loaded from a file is a stored value ("never checked against it", `layerNameError`'s own doc; spec D1's restore test (c) assumes such files exist), so every eye/lock/swatch press on such a layer throws `ArgumentError` out of the button's `onPressed` (LayerPanel has no catch), dispatches nothing, and the layer is stuck as it is — the same "dead end" S-6 ruled out for a hidden layer 0.
   Probe (temporary untracked test, removed; real output): `eye enabled: true` / `thrown: Invalid argument (name): A layer name cannot contain :.: "Walls:Ext"` / `visible after: true; undo depth 0`; same for `" Walls"` (`cannot start or end with a space`) and for a lock through `SetLayerCommand`.
   **Fix:** check `layerNameError` only when `record.name != old.name` (the layer-0 and decision-7 checks unchanged). Test: a layer added to the table directly with name `Walls:Ext` can be hidden, locked and recoloured through the user form (one undo step each), while renaming it to another invalid name is still refused; a panel test pressing its eye. Mutant: the unconditional check -> red. Optionally also wrap `LayerPanel._execute` in `on ArgumentError`/`on StateError` as `LayerPicker._choose` does, so a refused command never surfaces as an uncaught gesture exception. If the controller prefers not to touch the frozen engine, record it instead as a known limitation in the results note and the spec amendment (it is not there now).
