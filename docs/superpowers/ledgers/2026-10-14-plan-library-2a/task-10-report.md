## Concerns

- Task 11: `execute` already exists (Deviation 1); extend it. And a broken object must be frozen as it is locked (Deviation 4); otherwise a regeneration of a broken live object triggered by a neighbour's edit would touch it and be refused by the lock.
- M-L6f reddens by `PlanLocked` escaping `deleteSelection` rather than by a deletion: `PlanController.deleteSelection` does not catch `PlanLocked`; with the gates in place it never reaches it, but if Task 12's gates ever let a locked key through, `deleteSelection` would throw instead of answering false.
