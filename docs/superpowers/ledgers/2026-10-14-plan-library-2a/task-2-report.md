# Fix round 1 (review Important 1, the controller's ruling: widen the isolation pass)

Commit: `7ba09b31` fix(engine): probe isolates a broken place contributor (2a E2).

## What changed

### `parametric_system.dart` `probe`

The fix keeps the existing `reach`/`references` pass and adds a second isolation step after it:

1. The survey and its view are built as before, over `isolated()`. That predicate is the frozen predicate, plus `broken` when `broken` is non-empty.
2. Every other live place contributor in that survey is asked for `view.placeBoxOf(h)`, inside a try. The probed object itself is skipped, because its own box is asked in its own steps.
3. A contributor that throws is added to `broken`. If any contributor throws, the survey and the view are built again without it.

Only `placeBox` is pre-asked. `placedIn` reads `placeBoxOf` alone (`_placeAll`). `placeInput` is read only by the edit's trigger (`_triggered`), which `probe` never runs.

Cost:
- The view memoizes the boxes it asked, so a healthy contributor's `placeBox` still runs once per probe.
- The second survey is taken only when a contributor throws. In the healthy case, `debugReferenceCalls` stays at two per object per probe.
- The survey's own hot path (`_survey`, `_run`) is untouched.

The doc comment gains a paragraph on this step.

### `probe_test.dart`

- **E2-P1's expected call list now starts with `'placeBox P', 'placeBox Q'`.** These are the isolation pass's calls on the scene's two contributors. `beyondSurvey`'s comment says so. This changes a brief assertion, as a direct consequence of the ruling. It is stricter, because it pins the pass's calls and their order.
- **New test, E2-P6.** The scene is `frozenScene(tiles: false, places: true)` with `failingHooks = {'placeBox P'}`. It checks:
  - `probe(hS)` is null;
